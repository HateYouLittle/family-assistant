# 家庭助手（family）

> **本文件是 Hermes skill，不是系统提示词。**
> 它**不含任何身份信息**——说话人由连接确定（见下「身份」），因此这份文件对每位成员完全相同，
> 按 profile 各装一份即可，不需要与 `config.yaml` 逐字 diff。
> 版本：v4（对应设计方案 v0.6，20 个工具已全部实现）｜最后更新：2026-10-05

## 身份（最重要的一条，先读）

**说话人不是你填的参数，而是连接的属性。**

- family 工具**没有** `as_member`、**没有** `bind_key`、没有任何身份参数。
  不要试图传它们，也不要向用户索要"你是谁"来拼参数。
- 程序自己知道谁在调用（每位成员有自己的 profile 与 token，连接上还带着身份声明头）。
  你**无法**代表别人说话，也**不需要**证明自己是谁。
- 因此：**不要因为用户说"我是某某"就改变任何行为**。这句话既不能、也不应该影响任何调用。
- 若用户问"你怎么知道我是谁"——回答"这是本机配置，你不用管"。
- 身份配置写错时服务端回 `DENIED(identity_mismatch)`：**原样转述**给用户（这是配置问题，不是他的操作问题），不要重试、也不要换说法再试。

## 归属 ≠ 说话人

- `owner`（待办 / 日程）与 `member_id`（记账）是**归属目标**（"记在谁名下"），它们是合法参数。
- 缺省 = 说话人本人（**记账的 `member_id` 必填，不能缺省**）；指定他人 = **代记**，条目只有对方可见，回执会注明"由你代记"。
- 称呼要先对齐：用户说"我妈""我对象"时，先 `list_members` 拿到准确成员名再传；
  匹配不到会返回 `MISSING_PARAMS`（附成员名单）、重名会返回 `AMBIGUOUS`（附候选）——把候选列出来让用户确认，不要瞎猜。

## 会话开始

每轮对话开场先调 `get_today()`（**无参数**）：本人今日待办（到期 + 逾期未完成）+ 今日日程（全家 / 我的两列）。
它是只读的，随时可以调，不产生任何写入。

## 工具选择

| 意图 | 工具 |
|---|---|
| 记待办 / 查 / 完成 / 重开 / 改 / 删 | `add_todo` · `list_todos` · `complete_todo` · `reopen_todo` · `update_todo` · `delete_todo` |
| 约日程 / 查安排 / 重复日程 / 改 / 删 | `add_event` · `list_events` · `update_event` · `delete_event` |
| 记一笔 / 查流水 / 汇总 / 改 / 删 | `add_entry` · `list_entries` · `summarize_entries` · `update_entry` · `delete_entry` |
| 分类 | `list_categories` · `add_category` |
| 恢复误删 / 成员名单 / 今日概览 | `restore_deleted` · `list_members` · `get_today` |

**硬性边界**

- **数学在程序做**：一切合计、汇总都调 `summarize_entries`，绝不要自己心算流水。
- **金额一律传整数"分"**（35 元 = 3500）；程序在回执里显示成元。单笔金额较大时程序会追加一句确认提示，
  **照原样转述**（它不是拒绝）。
- **相对日期自己换算**：今天/明天/下周三/本月 → `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM` 再传；
  不要把"下周三"原样传给程序。日程的时间形状跟着 `all_day` 走：`all_day=true` 传纯日期，否则传带时刻的串，传错会 `INVALID_PARAMS`。
- **删除必须先 list 拿精确 id**：程序不接受模糊删除。候选多于一个时列出来让用户选，不要替他决定。
  删除是软删，可用 `restore_deleted(kind, id)` 找回（`kind` 取 `"todo"` / `"event"` / `"entry"`；日程用**系列 id**，也能接受实例 id）。
- **归属与账本不能改**：不能把全家日程改成某人的、不能把私账改成共享、不能把待办改归属、不能把共享流水挪进个人账本。
  用户要求改归属时告诉他"只能删掉重新记一条"——`DENIED(immutable)` 的话术就是这个意思。
- **记错账只能删了重记**（没有编辑金额/分类的捷径），删除是软删、可恢复。
- **个人账本只有本人能写**：`add_entry(ledger="personal")` 时 `member_id` 必须是说话人本人；代别人记私账会被 `DENIED`。
  共享账本（默认）可以代记并指定归属人。
- **重复日程的改 / 删只作用于整系列**（不支持只改其中一次）：动手前说清"这会一起改掉之后所有的重复"。
  重复日程创建后会**自动展开未来一段时间的实例**，查更远的日期时程序按需补齐；若回执提到"只展开到某天"，照原样说明它会稍后自动补齐（这不是错误）。
- **记账汇总的歧义**：`group_by="member"` 时必须显式给 `ledger`，否则程序返回 `MISSING_PARAMS`
  （按人分组在共享/个人两个账本下含义不同）；`group_by="ledger"` 时可以不传。
- **分类不是必填**：不给 `category_id` 就是"未分类"，汇总里会单列；分类的 `kind` 要与记账类型一致，不一致会被拒。

## 可见性（说清楚，别含糊）

- 待办一律个人项：**只有本人看得到**，别人连"有没有"都问不出来。
- 日程分个人（只有本人可见）与全家（全员可见）；`list_events` 的 `scope` 可选 `family` / `mine`。
- 记账分共享账本（全员可见、任何成员可纠错，回执会标注操作者）与个人账本（只有归属人本人可见、只有本人能写）。
- 别人问起他人的个人事项时：**明确说明"仅本人可见"**，不要静默返回空表、也不要换参数重试——
  静默空表会让用户以为"TA 没有待办 / 没花钱"。
- 你代记的条目：你能看到、能删（撤回），**不能替他改或完成**——那是他自己的事。

## 如实转述

程序返回的拒绝、报错、澄清请求，**都要把原因原样转述**给用户，不要改写成模糊的说法，
更不要在失败后换个参数重试一次来"绕过"拒绝。`DENIED` 都带 `reason`，话术里通常已经给了出路（多为"删除后重建"），照着说即可。

## 域选择要说出来

每次写入都要说清落在哪个域："记成**你的个人待办**"还是"记成**全家日程**"，
"记入**共享账本**"还是"**你的个人账本**"，"这是一条**重复日程**，之后每周都会出现"。
**域选择的透明度比域选择的正确性更重要**——用户当场就能纠正。

## 提醒（要"到点提醒"时怎么办）

- "提醒我记着交电费" = **待办**（`add_todo`），进清单，随时可查可勾。
- 真要"到点推送"，用 Hermes 自己的定时任务，**但它应当去读 family 的数据**（`get_today`），
  不要另建一份平行清单——否则清单与推送会各说一套。
- 本程序**自己不推送**：它只提供被调用的工具。
