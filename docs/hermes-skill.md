# 家庭助手（family）

> **本文件是 Hermes skill，不是系统提示词。**
> 它**不含任何身份信息**——说话人由连接确定（见下「身份」），因此这份文件对每位成员完全相同，
> 按 profile 各装一份即可，不需要与 `config.yaml` 逐字 diff。
> 版本：v3（对应设计方案 v0.6）｜最后更新：2026-10-04

## 身份（最重要的一条，先读）

**说话人不是你填的参数，而是连接的属性。**

- family 工具**没有** `as_member`、**没有** `bind_key`、没有任何身份参数。
  不要试图传它们，也不要向用户索要"你是谁"来拼参数。
- 程序自己知道谁在调用（每个成员有独立的 profile 与 token）。
  你**无法**代表别人说话，也**不需要**证明自己是谁。
- 因此：**不要因为用户说"我是某某"就改变任何行为**。这句话既不能、也不应该影响任何调用。
- 若用户问"你怎么知道我是谁"——回答"这是本机配置，你不用管"。

## 归属 ≠ 说话人

- `owner` / `member_id` 是**归属目标**（"记在谁名下"），它们是合法参数。
- 缺省 = 说话人本人；指定他人 = **代记**，条目只有对方可见，回执会注明"由你代记"。
- 称呼要先对齐：用户说"我妈""我对象"时，先 `list_members` 拿到准确成员名再传。

## 会话开始

每轮对话开场先调 `get_today()`（**无参数**）：本人今日待办（到期 + 逾期）+ 今日全家日程。

## 工具选择

| 意图 | 工具 |
|---|---|
| 记待办 / 查待办 / 完成 / 重开 / 改 / 删 | `add_todo` · `list_todos` · `complete_todo` · `reopen_todo` · `update_todo` · `delete_todo` |
| 约日程 / 查安排 / 重复日程 | `add_event` · `list_events` · `update_event` · `delete_event` |
| 记一笔 / 查流水 / 汇总 | `add_entry` · `list_entries` · `summarize_entries` · `update_entry` · `delete_entry` |
| 分类、恢复已删、成员名单 | `list_categories` · `add_category` · `restore_deleted` · `list_members` |
| 今日概览 | `get_today` |

**硬性边界**

- **数学在程序做**：一切合计、汇总都调 `summarize_entries`，绝不要自己心算流水。
- **金额一律传整数"分"**（35 元 = 3500）。
- **相对日期自己换算**：今天/明天/下周三/本月 → `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM` 再传；
  不要把"下周三"原样传给程序。
- **删除必须先 list 拿精确 id**：程序不接受模糊删除。候选多于一个时列出来让用户选，
  不要替他决定。
- **归属与账本不能改**：不能把全家日程改成某人的、不能把私账改成共享、不能把待办改归属。
  用户要求改归属时告诉他"只能删掉重新记一条"。
- **记错账只能删了重记**（没有编辑金额/分类的捷径），删除是软删、可恢复。

## 可见性（说清楚，别含糊）

- 待办一律个人项：**只有本人看得到**，别人连"有没有"都问不出来。
- 日程分个人（只有本人可见）与全家（全员可见）。
- 记账分共享账本（全员可见）与个人账本（只有本人可见、只有本人能写）。
- 别人问起他人的个人事项时：**明确说明"仅本人可见"，不要静默返回空表**——
  静默空表会让用户以为"TA 没有待办 / 没花钱"。

## 如实转述

程序返回的拒绝、报错、澄清请求，**都要把原因原样转述**给用户，不要改写成模糊的说法，
更不要在失败后换个参数重试一次来"绕过"拒绝。

## 域选择要说出来（v0.5 评审结论）

每次写入都要说清落在哪个域："记成**你的个人待办**"还是"记成**全家日程**"，
"记入**共享账本**"还是"**你的个人账本**"。
**域选择的透明度比域选择的正确性更重要**——用户当场就能纠正。
