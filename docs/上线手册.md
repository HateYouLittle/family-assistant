# 上线手册（family-assistant）

> 面向**部署这台机器的人**。命令按顺序执行即可；每一步都给「怎么确认它真的成了」。
> 身份模型见 `docs/设计方案.md` §3.2：**说话人 = 连接的属性**（每位成员一个 Hermes profile + 一个 family token + 一个身份声明头）。

## 0. 前置

- Node ≥ 22.5；本机已装（`node -v`）。
- 仓库：`family-assistant`。构建：`npm install && npm run build`。
- **不要**把 `data/` 目录放进任何同步/共享目录。

## 1. 配置环境变量（全部有默认值，只需改要改的）

| 变量 | 默认 | 说明 |
|---|---|---|
| `FA_MCP_HOST` / `FA_MCP_PORT` | `127.0.0.1` / `8347` | MCP 端点，**只绑回环**（设计 D2）。不要改成对外地址 |
| `FA_WEB_HOST` / `FA_WEB_PORT` | `127.0.0.1` / `8348` | 查看页/管理页。**缺省即不对外**；要家人手机访问必须显式设成**局域网网卡地址**（如 `192.168.x.x`）。用 `0.0.0.0` 会连所有网卡一起暴露，一般不需要 |
| `FA_DB_PATH` | `data/family-assistant.db` | SQLite（WAL） |
| `FA_TIMEZONE` | `Asia/Shanghai` | **家庭固定时区**；"今天/逾期/本周"全由它算，不读系统时区 |
| `FA_IDENTITY_HEADER` | `x-family-member` | 身份声明头名 |
| `FA_REQUIRE_IDENTITY_HEADER` | `true` | **保持 true**。置 false 会把"配错 token 静默串号"这个缺陷重新打开，仅供旧部署过渡 |

## 2. 起服务并确认

```bash
FA_WEB_HOST=192.168.x.x npm start      # 单进程同时起 MCP(回环) + 查看页(局域网)
curl -s http://127.0.0.1:8348/healthz  # 期望 {"ok":true,...}
```

- 启动日志会打印两个门面的地址；若查看页仍绑回环，日志会明确提醒"家人手机还打不开"。
- 系统级常驻建议用 systemd（`Restart=always`）。**本机当前是手工 nohup 起的**，正式上线要换成 systemd。

## 3. 初始化数据（管理端 CLI）

```bash
npm run admin -- member add 妈妈 --alias 老妈 --alias 王丽
npm run admin -- member add 爸爸
npm run admin -- member set-password 妈妈      # 查看页口令：不给 --password 会随机生成并只显示一次
npm run admin -- category list                 # 预置分类（支出 9 + 收入 4）应已存在

npm run admin -- admin set-password            # 管理页口令（未设置时管理页一律 503）
```

## 4. 给每位成员发 token，并写进**各自的** profile

```bash
npm run admin -- token generate 妈妈 --label "hermes profile"
```

输出里会有**明文 token（只显示这一次）**与可直接粘贴的配置片段。**每个成员的 profile 都要配两个头**：

```yaml
# ~/.hermes/profiles/妈妈/config.yaml
mcp_servers:
  family:
    url: "http://127.0.0.1:8347/mcp"
    headers:
      Authorization: "Bearer fam_…"
      X-Family-Member: "m-…"     # 值为该成员的 **id**（HTTP 头只能放 ASCII，别填中文名）
```

- 配错会**响亮失败**：token 属于 A、声明头写 B → `DENIED(identity_mismatch)`；缺声明头 → 同样拒绝。**不要**为了让配置"看起来能用"而关掉 `FA_REQUIRE_IDENTITY_HEADER`。
- 自检：`hermes -p 妈妈 mcp test family` → 应列出 20 个工具。

## 5. Hermes 侧的部署纪律（每条都有实测教训）

1. **收窄工具面**：该 profile 的对话通道只保留 family 工具集——
   命令行验证用 `-t family`；网关通道在 `platform_toolsets.<平台>` 里只留 `family`。
   **绝不能带 `terminal` / `file` / `code_execution`**：实测带全套工具时，模型会去读 token 明文文件、直接改库、甚至重启服务端。
2. **装 skill**：把 `docs/hermes-skill.md` 复制到 `~/.hermes/profiles/<成员>/skills/family-assistant/SKILL.md`（内容对所有人相同，**不含身份信息**）。
3. **DM 访问控制必须显式配**（不得依赖默认值：微信 `dm_policy` 的平台默认是 `open`）：设 allowlist 或 pairing，逐个确认家人能进、外人进不来。
4. **群策略保持 `disabled`、bot 不进群**：群里所有人的发言都会被当成该 profile 主人。
5. **cron 任务建在成员自己的 profile 下**（`profiles/<成员>/cron/jobs.json`），prompt 里**不写任何身份**——身份随 profile 自动确定。`deliver` 在正式部署时写具体 `platform:chat_id`（本地验证用 `local`，避免误推到真渠道）。
6. **查看页**：家人打开 `http://<局域网地址>:8348/`，选名字 + 自己的口令。局域网内**没有 HTTPS**，口令明文经过 Wi-Fi——这是家庭自托管的已知代价（设计 R9），别把它当 bug。

## 6. 备份（R5）

- 管理页「数据备份」一键下载（服务端用 `VACUUM INTO` 生成，**不要**直接拷 WAL 模式下的库文件）。
- 建议加一条**系统 cron** 每天做一次落盘备份（`sqlite3` 的 `VACUUM INTO` 或管理端同一条路径），并**别把备份放进共享目录**。
- 健康页会显示"最近一次备份时间"。

## 7. 待办：R10（每位成员各自的 bot 凭据）

- [ ] 每人一个 Hermes profile（各自 bot 凭据），确认**每人能和自己那个 bot 私聊**。
- [ ] 回到第 4、5 节：token + 声明头 + skill + 工具面收窄 + DM 白名单 + 群策略。
- [ ] 由一位**非开发者家人**确认"这个 bot 是我的"。

**若多 bot 凭据跑不通**：按设计文档 §11 的回退路径回到 v0.5.2 的通道绑定方案（`channel_overrides` + 成员参数），届时身份模型要重做——这也是为什么这一步必须先于人。

## 8. 故障对照

| 症状 | 先看哪里 |
|---|---|
| 工具调用全部 `DENIED(identity_mismatch)` | profile 的 token 与 `X-Family-Member` 是否属于同一成员；声明头值是否是**成员 id** |
| 工具调用 `DENIED(unknown_profile)` | token 是否被吊销、成员是否被软删；`npm run admin -- token list` |
| 看不到 family 工具 | profile/平台的工具面是否收了（`-t family`） |
| 管理页 503 | 还没设管理口令：`npm run admin -- admin set-password` |
| 查看页打不开 | `FA_WEB_HOST` 是否设成了局域网网卡地址 |
| cron 任务没产出 | 该 profile 的 `cron/output/<job_id>/`；健康页的"最近投递"；程序与 Hermes 同机故障（R4） |
